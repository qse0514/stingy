# Part 1 · Week 11 D3-D5：补齐 Agent 架构

**讲法约定**：每个大块先用架构图讲"它解决什么问题、在系统里的位置"，再看最小实现。语法级细节不主动讲，学员问才展开。

## Stingy 现状诊断：它还不是 Agent

现在是"**聊天 + 工具调用**"。真 Agent 缺的七块：

| 大块 | 现状 | 缺什么 |
|------|------|--------|
| **Planning 规划** | 一问一答，模型自由发挥 | 不会拆解"分析这个月哪类超支并给建议"这种多步任务 |
| **Memory 记忆** | 每次全量重发，无长期记忆 | 短期(context) / 长期(向量) / 结构化(DB) 三层分工 |
| **Reflection 自我纠错** | 无 | 工具失败怎么重试、结果不对怎么发现（"谎报成功"就是缺这层） |
| **HITL 人在环路** | 只有粗糙的金额阈值 | 高风险操作的确认流程 |
| **工具生态** | 3 个工具硬编码 | 工具多了怎么选、怎么检索 |
| **多 Agent 编排** | 无 | 什么时候该拆、什么时候是过度设计 |
| **Trace / Eval** | 一行 console.log | 看得见决策链、能回放、能打分 |

# Part 2 · Week 12：项目周 —— F1 Fantasy（能看见 AI 怎么想的车队经理联赛）

## 一句话定位（这句决定后面所有取舍）

> **不是"我做了个 F1 Fantasy"，是"我做了个能看见 AI 怎么想的 F1 Fantasy 联赛"。**

### 市场现状（已查证，不幻想原创）

- **F1 Fantasy 是 Formula 1 官方免费游戏**（fantasy.formula1.com），2026 赛季在运营，全球数百万玩家。预算上限/选车手/赛后结算/联盟排行榜全都有。
- **“LLM 当对手”目前还在研究/demo 阶段**（Alympics 论文、LLM Skirmish、AgentPitch 等），没有成熟产品 —— 但部分原因是 **模型玩策略游戏确实很烂**。

### 所以项目价值不在“发明新玩法”

| 期待 | 现实 |
|------|------|
| 做一个市面上没有的产品 | ❌ 5 天不现实 |
| 做一个能证明全栈 + AI 工程能力的作品 | ✅ 完全做得到，而且很有说服力 |

### 关键设计洞察：把弱点变成卖点

若卖点是“AI 很厉害能打赢你” → 它一定翻车（它确实不厉害）。
若卖点是“**看 AI 怎么做决策、怎么互相打脸、怎么犯蠢**” → 它蠢反而有观赏性，而且诚实。
→ **trace 从“调试工具”变成“产品功能”**，刚好压在 W11 学的 Observability 上。

## 最终形态

```
地基（必须先做，没它就没游戏）
  Fantasy 核心：预算选人 → 逐站概率化结算 → 积分排行

差异化（成本几乎不变，对手 Agent 本来就要写）
  3 个性格不同的 AI 车队经理（保守 / 激进 / 数据型）+ 你自己 = 4 队参战
  每站结束后可点开看每个 AI 的决策 trace：想了什么 / 查了什么 / 为何这么选

军师（可选，最后做）
  你自己的 AI 助手，会解释、要你确认（HITL）
```

**成本**：4 队 × 24 站，每队每站最多 1 次 LLM 调用 = 一赛季 ≤ 72 次。大部分站不需要换人，实际更少。

### ⭐ 工程原则（项目里反复用到）

> **Agent 数量 ≠ API 数量。** 一个 API key，多套 system prompt + 工具权限配置而已。
> **不是所有决策都值得花一次 LLM 调用。** 若要做 10 支车队，8 支用规则策略（零成本背景板），1-2 支“明星对手”用 LLM。LLM 只用在需要理解语义 / 权衡多个模糊因素的地方。

## 三个 playability 设计决策

1. **AI 对手（不只是军师）** —— 它们自己也组队跟你 PK。AI 组队是完全自主的 Planning（无人类确认）。
   → Multi-Agent 天然入口：军师 Agent（会解释、要你确认）vs 对手 Agent（自主、不解释、**看不到你的阵容** ← 权限设计真考点）
2. **概率化结算** —— 不直接用历史成绩，而是用历史数据算出每个车手在每类赛道的表现分布，每站按分布随机抽。
   → 数据真实（可信）+ 结果不可预测（有悬念，查历史也没用）+ 强者仍更可能赢（策略有意义）
3. **赛季逐站推进** —— 组队 → 看下站赛道特性 → 决定换不换人（换人次数有限）→ 推进开奖 → 结算 → 你 vs AI 排名 → 看 trace/复盘 → 循环。一赛季 20-30 分钟玩完，可重玩。

**playability 来源**：稀缺资源取舍（预算+换人次数）+ 对手压力 + 开奖多巴胺 + **看 AI 推理的观赏性**。参照物：Football Manager 极简版。

## 产品形态（五个页面）

1. **联赛首页** —— 4 队积分榜、赛季进度、推进按钮
2. **我的车队** —— 阵容、剩余预算、积分走势图、剩余换人次数
3. **车手市场** —— Table：身价/近期表现/涨跌，筛选排序
4. **组队/换人** —— 多步表单 + 实时预算校验 + Popconfirm 确认
5. **AI 决策回放** —— ⭐ 差异化页：每站每个 AI 经理的 trace（thought / 调了哪些工具 / 结果 / 最终决定），可展开对比

## 数据与规则决策（提前定下，避免现场扯）

| 项 | 决定 |
|----|------|
| 数据源 | 固定历史赛季（如 2024），开工时从 OpenF1 拉一次入库，**不依赖实时 API** |
| 车手身价 | 无官方数据 → 我们自己按历史积分折算，写进 README 是加分项 |
| 计分规则 | 简化三条：正赛名次积分 + 排位赛加分 + 完赛加分 |
| 赛季长度 | 24 站（可配置，调试时缩到 5 站） |
| 换人预算 | 整赛季 10 次（稀缺资源，造决策压力） |

### W12 Day 3 —— 3 个 AI 车队经理 + trace 前端展示（差异化）

### W12 Day 4 —— AI 军师 + HITL + Eval
- 军师 Agent：流式对话（复用 W10-11 链路），能提出组队方案

**DoD**：`npm run eval` 出报告；军师提案必须确认才生效。
